# Mando de Xbox: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jugar Nenúfar entero con un mando de Xbox, con textos de ayuda que cambian según el último dispositivo y vibración con los golpes.

**Architecture:** `core/mando.ts` (puro) traduce un mando leído a `Acciones`; `input/mando.ts` lee la API Gamepad en cada paso y vibra; `input/dispositivo.ts` recuerda el último dispositivo usado y el dibujo elige con él los textos de tablas `Record<Dispositivo, string>`.

**Tech Stack:** TypeScript strict, API Gamepad (`navigator.getGamepads`, `vibrationActuator.playEffect`), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-17-mando-design.md`

## Global Constraints

- `src/core/` sin navegador; la API Gamepad solo en `src/input/`; números en `src/data/controles.json` e `impacto.json`.
- Cero asignaciones en el bucle: la lectura del mando no crea arrays ni objetos por paso (`antes` es un array fijo); los textos por dispositivo son tablas hechas al cargar (`Record<Dispositivo, string>`), nunca un objeto literal creado al dibujar.
- Botones (asignación estándar): A 0 confirmar, B 1 cancelar, X 2 correr, Y 3 info, gatillo derecho 7 correr (valor > 0,5), Menú 9, cruceta 12-15; stick ejes 0 y 1 con zona muerta 0,35.
- Confirmar, cancelar, menú e info solo en el paso en que se pulsan; correr mientras se mantiene.
- Sin vibración si el Temblor efectivo es 0; la vibración escala con él.
- Letras «A», «B», «X», «Y», «Menú» tal cual, sin símbolos.
- Ningún número del equilibrado cambia. Español en código, comentarios y commits (`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`).
- Vitest: `npx vitest run tests/<archivo>`; suite: `npm test`, `npm run lint`, `npm run build`.

## Review Focus

1. **Mando conectado pero quieto** mientras se juega con teclado: no cambia el dispositivo ni pisa las teclas (devolver true solo con entrada real; el stick en reposo con deriva pequeña no cuenta) → test `mando en reposo no cuenta` (Task 1).
2. **Botón mantenido al pasar de una pantalla a otra** (A para cerrar un mensaje y seguir con A pulsada): no confirma dos veces → test `A mantenida confirma una vez` (Task 1).
3. **Mando que se desconecta** a mitad: el teclado y el táctil siguen; `antes` no deja botones «pegados» al reconectar → condición en Task 2 (si no hay mando, poner `antes` a false).
4. **Navegador sin `vibrationActuator`** (Safari, Firefox): `vibrar` no falla → condición en Task 4.
5. **Pantalla abierta cuando cambia el dispositivo** (pista de Equipo o Puntos): la pista cambia al momento, porque se lee al dibujar → comprobación en Task 5.

  - `A pulsada confirma`: A → `confirmar` true y devuelve true.
  - `A mantenida confirma una vez`: segundo paso con A aún pulsada (acciones nuevas) → `confirmar` false; soltar y volver a pulsar → true.

  - `diagonal`: ejes (0,7, 0,7) → `moverX` y `moverY` ≈ 0,707.
  - `la cruceta gana al stick`: eje 0 = −0,9 y botón 15 pulsado → `moverX` 1.
  - `mando en reposo no cuenta`: ejes (0,1, −0,1), nada pulsado → devuelve false y `acciones` sin tocar.

Devuelve true si hubo dirección por encima de la zona muerta, cruceta o cualquier botón pulsado. Botones que no existan en el mando cuentan como sueltos.
